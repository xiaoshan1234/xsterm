# UI 点击与显示用户测试用例

> 测试对象：XSTerm 桌面端（Tauri 2 + React）
> 测试重点：所有可点击元素的响应、各界面的显示状态与切换是否正常
> 测试方式：手工测试
> 文档版本：v1.1（基于 0.1.x 代码走查生成；v1.1 补充边界用例、自动化测试对齐与 tmux 现状修正）

---

## 0. 测试说明

### 0.1 测试环境

| 项目 | 要求 |
|---|---|
| 运行环境 | 应用运行于 **Windows（WebView2）**，手工测试操作 Windows 侧应用窗口 |
| 启动方式 | `npm run tauri dev`（完整应用，不要用独立浏览器打开 localhost:1420） |
| 本地会话 | 默认可用（Windows：PowerShell/pwsh/CMD/WSL；Linux：bash 等） |
| SSH 会话 | 需准备一台可达的 SSH 主机；无环境时 SSH 相关用例标记 `BLOCK` |
| 显示缩放 | 建议在 Windows 100% 与 125%/150% 缩放下各跑一遍界面显示类用例 |
| 辅助工具 | 显示类用例可用远程 WebDriver 栈截图取证（见 `test/README.md` 与附录 D） |

### 0.2 结果记录约定

- 每条用例结果记为：`PASS` / `FAIL` / `BLOCK`（环境不满足）/ `SKIP`
- 发现 bug 记录到 `doc/bug.md`，并回填对应用例编号
- 优先级定义：**P0** = 核心路径必测；**P1** = 重要功能；**P2** = 边界 / 视觉细节

### 0.3 已知限制（测试基线，不算新 bug）

以下为当前代码的已知缺口，测试时如复请标记"已知问题"：

| # | 已知限制 | 影响用例 |
|---|---|---|
| K1 | 侧边栏 Logs 按钮与 Ctrl+L 当前为空实现，点击/按下无任何反应 | TC-207、TC-1404 |
| K2 | 设置页快捷键列表展示了 "Open settings: Ctrl+, "，但该快捷键未实现 | TC-1405 |
| K3 | 窗口标签拖拽仅有视觉反馈（透明度变化），松手后不会重排 | TC-609 |
| K4 | Workspace/Window 管理面板的删除按钮无二次确认，点击立即删除 | TC-406、TC-504 |
| K5 | 终端配色主题不持久化，重启后回到 dark（应用明暗模式会持久化） | TC-1204、TC-1505 |
| K6 | UI 基于 MUI 组件库实现，部分文案为英文、断连提示为中文，属现状 | 全部 |

### 0.4 与自动化测试的关系

- 自动化冒烟测试 `test/smoke.spec.ts`（`npm run test:system`）覆盖首屏渲染，其与当前 UI 的一致性状况见**附录 D**。
- `test/remote/` 远程 WebDriver 栈可从 WSL 驱动 Windows 侧应用（`npm run test:remote:drive`），适合为显示类用例截图取证。
- 本文档手工用例与自动化冒烟互补：冒烟只验证"渲染存在"，点击交互与状态切换以手工用例为准。
